01 / DATA STRUCTURES

Lists

Lists are ordered, sequential collections of elements. C949 tests three types: arrays (static), singly linked lists, and doubly linked lists.

Array / Python List

A contiguous block of memory. Each element accessed via index in O(1). In Python, the built-in list is a dynamic array.

Rules

  • Elements stored at consecutive memory addresses.
  • Index access is O(1) — direct offset calculation.
  • Insertion/deletion at middle requires shifting elements → O(n).
  • Append to end is amortized O(1) (Python dynamic array doubles capacity).

Key Operations

OperationBestAverageWorst
Access by indexO(1)O(1)O(1)
Search (unsorted)O(1)O(n)O(n)
Insert at endO(1)O(1)*O(n)
Insert at indexO(1)O(n)O(n)
Delete at indexO(1)O(n)O(n)
# Python list operations
arr = [10, 20, 30, 40]
arr.append(50)          # O(1) amortized — adds to end
arr.insert(2, 99)       # O(n) — shifts elements right
arr.pop()               # O(1) — removes last element
arr.pop(1)             # O(n) — removes at index, shifts
x = arr[0]             # O(1) — direct index access
print(arr.index(99))   # O(n) — linear search

Singly Linked List

Each node holds data + a next pointer. The list maintains a head pointer; traversal is one-directional only.

Rules

  • No index — must traverse from head to reach any element.
  • Prepend is O(1): create node, point its next to current head, update head.
  • Append requires traversal to tail → O(n) without a tail pointer.
  • Delete requires tracking the previous node.

Procedure: Insert After a Node

  1. Create a new node with the given data.
  2. Set new_node.next = current_node.next
  3. Set current_node.next = new_node
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class SinglyLinkedList:
    def __init__(self):
        self.head = None

    def prepend(self, data):     # O(1)
        node = Node(data)
        node.next = self.head
        self.head = node

    def append(self, data):      # O(n) without tail ptr
        node = Node(data)
        if not self.head:
            self.head = node; return
        cur = self.head
        while cur.next: cur = cur.next
        cur.next = node

    def search(self, key):       # O(n)
        cur = self.head
        while cur:
            if cur.data == key: return cur
            cur = cur.next
        return None
💡 Note: Singly linked list delete questions commonly ask you to track the previous node. Use a two-pointer walk: prev and curr.

Doubly Linked List

Each node holds data + next + prev. Enables O(1) backward traversal and simpler deletion (no need to track predecessor separately).

Rules

  • Two pointers per node — slightly more memory than singly linked.
  • Deletion of a known node is O(1) — adjust both neighbors' pointers.
  • Common implementation for deques, LRU caches.
  • Python's collections.deque is a doubly linked list under the hood.

Procedure: Delete a Known Node

  1. If node.prev exists → set node.prev.next = node.next
  2. If node.next exists → set node.next.prev = node.prev
  3. If node is head → update head = node.next
  4. If node is tail → update tail = node.prev
💡 Array vs. Linked List Decision Rule:
✅ Use array/list when you need fast random access by index.
✅ Use linked list when you need fast insertions/deletions at arbitrary positions and don't need index access.

Stacks & Queues

Stack — Last In, First Out (LIFO)

Think of a stack of plates: you add and remove from the top only.

Core Operations (all O(1))

  • push(item) — add to top
  • pop() — remove and return top
  • peek() / top() — view top without removing
  • is_empty() — returns True if stack has no items

Rules

  • Only the top element is accessible at any time.
  • Can be implemented with a Python list (append = push, pop = pop).
  • Common uses: function call stack, undo operations, expression parsing, DFS.
# Stack using Python list
stack = []
stack.append(1)   # push  → stack = [1]
stack.append(2)   # push  → stack = [1, 2]
stack.append(3)   # push  → stack = [1, 2, 3]
top = stack.pop() # pop   → returns 3, stack = [1, 2]
peek = stack[-1]  # peek  → 2 (no removal)

# Stack using collections.deque (preferred for performance)
from collections import deque
stack = deque()
stack.append(10)
stack.pop()       # O(1) guaranteed
💡 Note: The exam often asks you to trace push/pop operations. Write out each state after every operation — don't try to do it in your head.

Queue — First In, First Out (FIFO)

Think of a checkout line: items added to the back, removed from the front.

Core Operations (all O(1) with deque)

  • enqueue(item) — add to back
  • dequeue() — remove and return front
  • peek() — view front without removing
  • is_empty() — returns True if queue is empty

Rules

  • Do NOT use a Python list for queues (list.pop(0) is O(n)). Use collections.deque.
  • Common uses: BFS traversal, task scheduling, print spoolers.
  • Priority Queue: uses a heap to always dequeue the highest-priority item.
from collections import deque

queue = deque()
queue.append(1)        # enqueue → back  [1]
queue.append(2)        # enqueue → back  [1,2]
queue.append(3)        # enqueue → back  [1,2,3]
front = queue.popleft() # dequeue → front returns 1, [2,3]
peek  = queue[0]       # peek front → 2

Deque — Double-Ended Queue

Supports insertion and removal from both ends in O(1). Generalizes both stack and queue.

from collections import deque
d = deque([1,2,3])
d.appendleft(0)  # [0,1,2,3]
d.append(4)      # [0,1,2,3,4]
d.popleft()      # removes 0 → [1,2,3,4]
d.pop()          # removes 4 → [1,2,3]
⚠️ Common Mistake: Confusing enqueue (back) with push (top of stack). Read carefully: "What is at the FRONT of the queue after these operations?" not the back.

Hash Tables

Hash tables map keys to values via a hash function. Average O(1) for insert, delete, and search. C949 tests three collision strategies: linear probing, quadratic probing, and chaining.

Hash Function

Core Formula

bucket_index = hash(key) % table_size
A good hash function distributes keys uniformly to minimize collisions.

Load Factor

load_factor = number_of_items / table_size

  • Keep load factor ≤ 0.7 for linear probing; ≤ 0.5 for quadratic probing.
  • When load factor exceeds threshold → rehash: create larger table, re-insert all items.
  • Python dict rehashes when load factor hits ~0.67.

Linear Probing (Open Addressing)

Rules

  • On collision at index i, try i+1, i+2, i+3, ... (wrapping around).
  • Formula: probe_index = (hash(key) + j) % table_size where j = 1, 2, 3…
  • Problem: primary clustering — long chains of filled buckets build up, slowing future lookups.

Procedure: Insert

  1. Compute index = hash(key) % size
  2. If slot is empty → insert here.
  3. If slot is taken → probe index+1, index+2, … (wrap with mod) until empty slot found.
  4. Insert at empty slot.

Procedure: Search

  1. Compute starting index.
  2. Probe forward. If key matches → found.
  3. If empty slot encountered → key not present.
  4. If entire table probed without finding → not present.
class LinearProbingHashTable:
    def __init__(self, size=10):
        self.size  = size
        self.table = [None] * size

    def _hash(self, key):
        return hash(key) % self.size

    def insert(self, key, value):
        idx = self._hash(key)
        for j in range(self.size):
            probe = (idx + j) % self.size
            if self.table[probe] is None:
                self.table[probe] = (key, value)
                return
        raise Exception("Table full")
💡 Note: Linear probing questions typically give you a table size, a hash function (often key % size), and a list of keys to insert. Draw the array and fill it step by step — don't skip ahead.

Quadratic Probing

Rules

  • Formula: probe_index = (hash(key) + j²) % table_size where j = 1, 2, 3…
  • Reduces primary clustering (consecutive filled slots).
  • Can suffer secondary clustering (keys with same hash follow same probe sequence).
  • ⚠️ Not guaranteed to find a slot unless table size is prime and load factor ≤ 0.5.

Procedure: Insert with Quadratic Probing

  1. Compute start = hash(key) % size
  2. j = 0: try index = (start + 0²) % size = start
  3. j = 1: try index = (start + 1) % size
  4. j = 2: try index = (start + 4) % size
  5. j = 3: try index = (start + 9) % size … and so on
  6. Insert at first empty slot found.
# Quadratic probe sequence for key "cat", hash=3, size=10
# j=0: (3+0)%10 = 3   → occupied?
# j=1: (3+1)%10 = 4   → occupied?
# j=2: (3+4)%10 = 7   → occupied?
# j=3: (3+9)%10 = 2   → empty → INSERT HERE

def quad_probe(start, j, size):
    return (start + j**2) % size
⚠️ Key Difference to Memorize:
Linear: j = 1,2,3,4… (step of 1)
Quadratic: j² = 1,4,9,16… (growing jumps)

Separate Chaining

Rules

  • Each bucket holds a linked list (or Python list) of all keys that hash to it.
  • No collision — multiple items can share a bucket.
  • Search time degrades to O(n) if all keys hash to the same bucket.
  • Handles any load factor without rehashing being strictly required.
class ChainingHashTable:
    def __init__(self, size=10):
        self.buckets = [[] for _ in range(size)]

    def insert(self, key, value):
        idx = hash(key) % len(self.buckets)
        self.buckets[idx].append((key, value))

Trees & Binary Search Trees

Tree Anatomy — Terms You Must Know

  • Root — topmost node (no parent)
  • Leaf — node with no children
  • Height — longest path from root to a leaf
  • Depth — distance from root to a specific node
  • Internal node — any non-leaf node
  • Subtree — a node and all its descendants
  • Binary tree — each node has at most 2 children (left, right)

BST Property (⚡ Must Memorize)

Binary Search Tree Invariant

For every node N:
• All values in left subtree < N.key
• All values in right subtree > N.key

BST Operations

Procedure: BST Search

  1. Start at root.
  2. If key == node.key → found!
  3. If key < node.key → go left.
  4. If key > node.key → go right.
  5. If node is None → not found.
def search(node, key):
    if node is None or node.key == key:
        return node
    if key < node.key:
        return search(node.left, key)
    return search(node.right, key)

Procedure: BST Insert

  1. If tree is empty → new node becomes root.
  2. Navigate left/right using BST property.
  3. When you reach None → insert new node there.
def insert(node, key):
    if node is None:
        return Node(key)
    if key < node.key:
        node.left  = insert(node.left, key)
    elif key > node.key:
        node.right = insert(node.right, key)
    return node   # duplicates ignored

Procedure: BST Delete (3 Cases)

Case 1: Node is a leaf

Simply remove it (set parent's pointer to None).

Case 2: Node has one child

Replace the node with its single child.

Case 3: Node has two children

Find the in-order successor (smallest node in right subtree). Copy its value into current node. Delete the in-order successor.

💡 In-order Successor Trick: Go right once, then keep going left until you can't. That's the in-order successor (smallest in right subtree).

Tree Traversals — The Big 3

NameVisit OrderResult on BSTMemory Hook
In-orderLeft → Node → RightSorted ascending ✅In = sorted
Pre-orderNode → Left → RightRoot firstPre = root first
Post-orderLeft → Right → NodeRoot lastPost = root last
def inorder(node):    # Left → Node → Right
    if node:
        inorder(node.left)
        print(node.key)
        inorder(node.right)

def preorder(node):   # Node → Left → Right
    if node:
        print(node.key)
        preorder(node.left)
        preorder(node.right)

def postorder(node):  # Left → Right → Node
    if node:
        postorder(node.left)
        postorder(node.right)
        print(node.key)
⚠️ Attention: A very common question type shows a BST diagram and asks "what is the in-order traversal?" — always produces sorted output from a valid BST.

BST Complexity

💡 Skewed BST Tip: If you insert keys in sorted order (1,2,3,4,5…) into a BST, it degrades to a linked list → O(n). This is WHY we need balanced trees (AVL).

Balanced Trees — AVL Trees

An AVL tree is a self-balancing BST that guarantees O(log n) operations by maintaining a balance factor at every node. C949 focuses exclusively on AVL trees for balanced BSTs.

Balance Factor

Balance Factor Formula

BF(node) = height(left subtree) − height(right subtree)

✅ Valid balance factors: -1, 0, +1
❌ Imbalanced: BF ≤ -2 or BF ≥ +2 → must rotate

The 4 Rotation Cases

Left-Left Case → Right Rotation

BF = +2 at node, BF = +1 at left child. The tree is heavy on the left-left side.

  1. Let A = imbalanced node, B = A's left child.
  2. B becomes the new subtree root.
  3. A becomes B's right child.
  4. B's old right child becomes A's new left child.
# Right rotation
def rotate_right(A):
    B = A.left
    A.left = B.right    # step 4
    B.right = A         # step 3
    update_height(A)
    update_height(B)
    return B            # B is new root

Right-Right Case → Left Rotation

BF = -2 at node, BF = -1 at right child. Mirror image of LL case.

  1. Let A = imbalanced node, B = A's right child.
  2. B becomes the new subtree root.
  3. A becomes B's left child.
  4. B's old left child becomes A's new right child.
# Left rotation
def rotate_left(A):
    B = A.right
    A.right = B.left
    B.left = A
    update_height(A)
    update_height(B)
    return B

Left-Right Case → Double Rotation

BF = +2 at node, BF = -1 at left child. Cannot fix with single rotation.

  1. Left rotate A's left child (convert to LL case).
  2. Right rotate A (now an LL case).
💡 Memory Hook: LR = two rotations. First go Left (rotate left child left), then go Right (rotate root right). The name tells you the imbalance direction, not the rotation direction.

Right-Left Case → Double Rotation

BF = -2 at node, BF = +1 at right child. Mirror of LR.

  1. Right rotate A's right child (convert to RR case).
  2. Left rotate A (now an RR case).

AVL vs. Plain BST

OperationPlain BST (avg)Plain BST (worst)AVL Tree
SearchO(log n)O(n)O(log n)
InsertO(log n)O(n)O(log n)
DeleteO(log n)O(n)O(log n)
💡 Rotation Trick: To identify which rotation to use, look at the imbalanced node's BF and its heavier child's BF:
BF=+2, child BF=+1 → LL → single right rotation
BF=-2, child BF=-1 → RR → single left rotation
BF=+2, child BF=-1 → LR → double (left then right)
BF=-2, child BF=+1 → RL → double (right then left)

Heaps & Treaps

Heap

A complete binary tree satisfying the heap property. Stored efficiently as an array.

Max-Heap Property

Every parent's key ≥ its children's keys. Root holds the maximum.

Min-Heap Property

Every parent's key ≤ its children's keys. Root holds the minimum.

Array Representation

For a node at index i (0-indexed):

  • Left child: 2*i + 1
  • Right child: 2*i + 2
  • Parent: (i-1) // 2

Procedure: Insert (Percolate Up)

  1. Add new element at the end of the array.
  2. Compare with parent. If heap property violated → swap.
  3. Repeat step 2 until parent is valid or root reached.

Procedure: Remove Max / Min (Percolate Down)

  1. Save root value (the max/min).
  2. Move last element to root position.
  3. Remove last element.
  4. Percolate down: compare root with children, swap with larger child (max-heap), repeat.
  5. Return saved value.
import heapq

# Python heapq is a MIN-heap by default
h = []
heapq.heappush(h, 5)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
print(heapq.heappop(h))   # → 1 (minimum)

# MAX-heap trick: negate values
max_heap = []
for x in [5, 1, 3]:
    heapq.heappush(max_heap, -x)
print(-heapq.heappop(max_heap))  # → 5 (maximum)
💡 Heap = Priority Queue: When asked "which structure implements a priority queue?" → Heap. Always.

Heapsort

  1. Build a max-heap from the array: O(n)
  2. Repeatedly extract the max and place at end of array.
  3. Each extraction: O(log n). Total: O(n log n)

Treap

A Treap combines a BST with a heap. Each node has both a key (BST property) and a randomly assigned priority (heap property).

Treap Dual Property

• BST property: keys are ordered (left < node < right)
• Heap property: every parent's priority ≥ children's priorities (max-heap on priority)

Why Treaps?

  • Random priorities cause the tree to be balanced on average without complex rotation bookkeeping like AVL.
  • Expected height: O(log n)

Procedure: Treap Insert

  1. Insert key using standard BST insert procedure.
  2. Assign a random priority to the new node.
  3. If new node's priority > parent's priority → rotate to maintain heap property.
  4. Use left or right rotation based on which child the new node is.

Procedure: Treap Delete

  1. Find the node using BST search.
  2. Reduce its priority to -∞ (or 0 for min-heap variant).
  3. Percolate the node down via rotations until it becomes a leaf.
  4. Remove the leaf node.
⚠️ Note: Treaps are tested conceptually in C949. Focus on understanding the dual property and why random priorities keep the tree balanced — you are unlikely to need to code a full treap from scratch.

Heap Complexity Summary

OperationTime
Insert (percolate up)O(log n)
Remove min/max (percolate down)O(log n)
Peek min/max (root)O(1)
Build heap (heapify)O(n)
HeapsortO(n log n)

A graph G = (V, E) consists of vertices (nodes) and edges (connections). Graphs generalize trees — a tree is a connected acyclic graph.

Graph Traversal Algorithms

Breadth-First Search (BFS)

Explores all neighbors before going deeper. Uses a queue. Finds shortest path in unweighted graphs.

  1. Enqueue start vertex. Mark as visited.
  2. Dequeue vertex. Process it.
  3. Enqueue all unvisited neighbors. Mark them visited.
  4. Repeat until queue is empty.
from collections import deque

def bfs(graph, start):
    visited = set([start])
    queue   = deque([start])
    while queue:
        v = queue.popleft()
        print(v)
        for neighbor in graph[v]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
# Time: O(V + E)
💡 BFS = Queue, DFS = Stack (or recursion). This is one of the most commonly tested graph facts.

Depth-First Search (DFS)

Explores as deep as possible before backtracking. Uses a stack (or recursion).

def dfs(graph, start, visited=None):
    if visited is None: visited = set()
    visited.add(start)
    print(start)
    for neighbor in graph[start]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)
# Time: O(V + E)

Dijkstra's Shortest Path

Finds the shortest path from a source to all vertices in a weighted graph. Uses a priority queue (min-heap).

  1. Set dist[source] = 0, all others = ∞.
  2. Add source to min-heap.
  3. Pop vertex with minimum distance.
  4. For each neighbor: if dist[current] + edge_weight < dist[neighbor] → update dist[neighbor] and push to heap.
  5. Repeat until heap is empty.
import heapq

def dijkstra(graph, src):
    dist = {v: float('inf') for v in graph}
    dist[src] = 0
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]: continue
        for v, w in graph[u]:
            nd = dist[u] + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(heap, (nd, v))
    return dist
# Time: O((V + E) log V)
⚠️ Dijkstra Limitation: Does NOT work with negative edge weights. Use Bellman-Ford for negative weights (not in C949 scope, but good to know).

09 / DATA STRUCTURES

B-Trees

A B-tree is a self-balancing multi-way search tree designed for systems that read/write large blocks of data (databases, file systems). Unlike BSTs, each node can hold multiple keys and have many children.

B-Tree Rules (Order m)

B-Tree Invariants

1. Every node has at most m children (m = order)
2. Every non-root internal node has at least ⌈m/2⌉ children
3. Root has at least 2 children (unless it's a leaf)
4. All leaves are at the same level
5. A node with k children contains k-1 keys

B-Tree vs BST

PropertyBSTB-Tree (order m)
Keys per node1Up to m-1
Children per nodeUp to 2Up to m
HeightO(n) worst caseO(log n)
Best forIn-memoryDisk/database I/O

Procedure: B-Tree Insert

  1. Find the appropriate leaf node using BST-like comparison.
  2. Insert the key in sorted order within that leaf.
  3. If the node now has m keys (overflow) → split it.
  4. Move the median key up to the parent.
  5. If parent overflows → split parent too (propagate up).
  6. If root splits → create a new root, tree height increases by 1.
💡 B-Tree Key Insight: B-trees grow upward (splits push keys up to root), unlike BSTs which grow downward. This is why all leaves stay at the same level.
⚠️ Scope: C949 tests B-tree concepts — the order, node capacity rules, split behavior, and why B-trees are used for databases. Deep implementation is less likely. Know the rules and how to trace an insert with a split.

Big O Rules

  • Drop constants: O(3n) → O(n)
  • Drop lower-order terms: O(n² + n) → O(n²)
  • Sequential steps add: O(n) + O(m) → O(n + m)
  • Nested loops multiply: O(n) inside O(n) → O(n²)
  • Halving = log: Any algorithm that halves input each step → O(log n)

Binary Search Procedure

  1. Set low = 0, high = len(arr) - 1
  2. mid = (low + high) // 2
  3. If arr[mid] == target → found at mid
  4. If arr[mid] < target → low = mid + 1 (search right half)
  5. If arr[mid] > target → high = mid - 1 (search left half)
  6. Repeat until found or low > high → not found
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if   arr[mid] == target: return mid
        elif arr[mid]  < target: low  = mid + 1
        else:                   high = mid - 1
    return -1  # not found

Recursion & Space Complexity

  • Each recursive call adds a stack frame → space complexity = O(call depth).
  • Binary search recursively → O(log n) space.
  • Merge sort → O(n) space for auxiliary arrays.
  • Iterative versions usually reduce space to O(1).

11 / DYNAMIC DATA STRUCTURES

Dynamic Data Structures

This is the applied area — the goal is to choose the right structure for a given scenario, predict how structures behave as data scales, and reason about trade-offs. It bridges Sections 1–10 into real decisions.

⚠️ What "Dynamic" Means Here: "Dynamic" refers to structures whose size changes at runtime (as opposed to fixed-size arrays). This domain focuses on scalability reasoning — how does this structure behave as n grows from 100 to 1,000,000?

The Core Decision Framework

For any scenario, ask these questions in order:

  1. Do I need fast access by index/key? → Array (index) or Hash Table (key)
  2. Do I need sorted order? → BST, AVL Tree, or sorted array
  3. Do I need fast insert/delete at arbitrary positions? → Linked List
  4. Do I need the min or max quickly? → Heap / Priority Queue
  5. Do I need LIFO order? → Stack
  6. Do I need FIFO order? → Queue
  7. Do I need to model relationships/connections? → Graph
  8. Is data stored on disk / very large? → B-Tree

Structure Selection Scenarios

🎮 Scenario: Undo / Redo in a text editor
Each action must be undoable in reverse order. New actions push onto history, Undo pops the last one.
✅ Best choice: Stack (LIFO). Each action is pushed; undo pops the most recent.
🖨️ Scenario: Print job spooler
Jobs arrive from multiple computers and must be printed in the order received. No job should jump the queue.
✅ Best choice: Queue (FIFO). First job submitted is first to print.
🏥 Scenario: Hospital emergency room triage
Patients arrive continuously. Most critical patients must be treated first regardless of arrival order.
✅ Best choice: Priority Queue / Min-Heap. Severity score = priority. O(log n) insert and O(log n) extract-min.
📖 Scenario: Dictionary / spell checker lookup
Given 500,000 words, need to check whether any input word is valid in near-instant time.
✅ Best choice: Hash Table (set). O(1) average membership test. BST is O(log n) — slower at scale.
🗺️ Scenario: GPS turn-by-turn navigation
Road network with intersections (nodes) and roads (weighted edges). Find shortest driving route.
✅ Best choice: Weighted Graph + Dijkstra's Algorithm. Roads are edges with distance/time weights.
🗃️ Scenario: Database index for 10 million records
Records stored on disk. Need fast search, insert, and delete. Data won't fit in RAM. Disk reads are expensive.
✅ Best choice: B-Tree. Minimizes disk I/O by keeping many keys per node. Used by MySQL, PostgreSQL indexes.
📊 Scenario: Leaderboard — always show top 10 scores
Scores are added continuously. Need to quickly retrieve the top 10 at any moment.
✅ Best choice: Max-Heap (or Min-Heap of size 10). O(1) peek at max, O(log n) insert.
🔗 Scenario: Social network — friends of friends
Users are connected to other users. Need to find if person A can reach person B within 3 hops.
✅ Best choice: Undirected Graph + BFS. BFS naturally explores level-by-level (hop-by-hop).

Dynamic Resizing Behaviors

  • Python list (dynamic array): doubles capacity when full → amortized O(1) append, but occasional O(n) copy.
  • Hash table: rehashes when load factor exceeds threshold → amortized O(1), spikes on rehash.
  • BST (unbalanced): degrades to O(n) on sorted input — no self-correction.
  • AVL / B-Tree: self-correcting → maintains O(log n) regardless of insertion order.
  • Heap: complete binary tree stays balanced by definition — no rotation needed.
💡 The Golden Pattern: Dynamic Data Structures questions often look like: "A program must do X millions of times as data grows. Which structure minimizes time complexity?" — translate the requirement into an operation (search? insert? ordered retrieval?) then pick the structure with the best Big O for that operation at scale.
